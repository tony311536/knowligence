Knowligence · Project Evaluator Guide

面向开源数据栈与知识探索者的版本与证据感知工作台

在数据工程与专业文献频繁演进的场景中，Knowligence（知更）通过构建只读四层语义知识图谱， 限定目标版本与范围、对照精选官方出处、解释新旧差异（公网站点提供预置拓扑与静态影响示例；本地环境支持 Python AST 语法定位）， 并在证据不足时严守 insufficient 诚实拒答边界。

🎯 核心痛点与行业背景 (The Problem)

传统检索增强生成 (RAG) 与通用大模型在专业知识密集与版本敏感领域的三大失效根源

1. 幻觉输出与黑盒结论

传统问答倾向于“合理猜测”，在面对专业参数、行业指南与版本升级条款时缺乏确定性出处锚点，导致结论看似顺畅实则难以核验。

2. 版本混淆与断代失效

技术库版本迭代（例如 NumPy 1.26 到 2.0）或合规准则更新时，API 废弃与行为变更是条件触发的。通用系统极易把旧规则强套在新版本上。

3. 缺乏边界与盲目作答

现有问答系统普遍缺失可靠的“证据边界（Evidence Boundary）”。在收录资料不足时盲目生成推断，直接给工程升级决策带来高危隐患。

💡 解决方案与产品架构 (The Solution)

以“版本与证据感知”为核心，构建可追溯、可验证、有边界的立体化知识工作台

📐 四层有向实体图谱

将离散信息解构为四大类型对象：来源文档 (Source) → 知识声明 (Claim) → 知识主题 (Topic) → 工作资产 (Asset)，建立清晰的结构化脉络。

🔗 官方出处与范围绑定

精选收录的声明绑定官方发布者、指南出处、适用版本或资料集范围与摘录原文，为展示结论提供可核对的出处线索。

🎨 关系双重编码机制

通过线型与色彩双重编码：已证实支撑 (proven, 实线)、主题归属 (applies, 实线箭头) 与 候选结构关联 (candidate, 虚线)，严防未核验边被误认作事实。

🛡 确定性拒答安全底线

当用户提出的问题超出当前实验场已收录的证据范围时，系统坚持给出 insufficient 拒答并展示证据缺口，不凭空捏造结论。

⚙️ 技术栈与工程全景 (Technical Stack)

无依赖高性能纯前端内核、受限边缘在线筛选与本地只读安全分析的精巧组合

分层模块 核心技术与实现 设计考量与安全边界
前端计算内核 web/atlas-core.js 纯函数无框架内核，ESM 模块化，SVG 矢量拓扑与脑图渲染 无庞大前端框架运行时；零外部 CDN 脚本，离线即可运行核心推理与图谱布局计算。

✨ 核心特色与创新点 (Key Innovations)

把严肃的版本演化与知识溯源转化为直观易懂、诚实可信的探索体验

🏷 1. 结构化证据链与生命周期范围感知

知识不是孤立静态的陈述。Knowligence 将结论与适用版本或资料集范围关联，在技术升级场景（如 NumPy 1.26.4 与 2.0.0）支持单版本查看与跨版本差异对比，并指出声明的适用生命周期与范围。

🛑 2. 基于证据边界的保守拒答机制

拒答率不等于错误率，而是安全基石。离线预设规则在证据不足时给出 insufficient 响应，向用户如实反馈收录范围之外的证据缺口，避免脱离证据盲目推断。

🧭 3. 探险式人机协同搭档 Captain Kiko

以可爱的“知识探险搭档 Captain Kiko”降低面对晦涩技术文档时的心理门槛。提供可预览的搭档换装衣橱与沉浸式引导，兼顾工程严肃性与探索趣味性。

🔍 4. 彻底透明的诚实披露原则

系统明确区分本地浏览器探索、受限在线模型精选与未接通的远端后端服务，不在界面和文档中将本地数据包装为企业级云端历史，绝不进行虚假夸大。

🚀 系统使用与评估指南 (Usage Steps)

五步上手，完整体验从资料接入、图谱拓扑、版本对比到证据驱动问答的全流程

1 切换工作空间实验场

点击左侧边栏顶部的“工作空间”切换按钮，可在“天文数据探险（默认）”、“绿色酒店能耗”和“NumPy 升级影响”三个实验场间无缝切换，加载对应精选语料。

2 探索知识图谱与层级脑图

在“知识图谱”中通过鼠标缩放、拖拽与点击节点查看四层对象连接；在“知识脑图”中按主题大纲层级收展；选择来源或声明节点可查看相关出处。

3 资产目录与本地笔记

在“资产目录”中检视收录的文档、声明、主题与代码资产；可导入本地 Markdown 笔记或自建笔记，笔记通过双向链接 [[主题]] 建立候选关系，内容仅存留于本地浏览器。

4 唤起 Captain Kiko 进行证据问答

点击右下角助手按钮唤出 Captain Kiko。输入问题后，系统默认执行本地确定性规则预设匹配，返回带出处引用的可靠回答；若超出范围则给出标准证据不足拒答。

5 可选在线模型声明筛选

若需由大模型辅助筛选证据，登录 ChatGPT 账号后主动点击「MOI 在线询问」，将在 Cloudflare Worker 限额内调用 Genesis 在线模型对现有精选证据进行受控声明筛选（全站每日共享 100 次限额，北京时间午夜重置；该功能仅为受控声明筛选，不提供自由生成或流式对话）。

🧪 三大已收录精选公开实验场 (Curated Public Labs)

基于精选公开资料构建的开源与行业示范资料集

🔭 天文数据探险

默认实验场。基于 NASA 与 ESA/Webb 科研文献，收录系外行星定义与多样性、光年尺度、凌日现象观测及透射光谱分析等 7 条来源记录与 10 条精选声明（该资料集为单一科普知识集合，不包含软件版本划分）。

🏨 酒店能耗与水资源基准

收录 6 份官方来源记录、4 篇指导文档（包括 U.S. EPA ENERGY STAR 2024 旅宿业巡检清单与 WaterSense H2Otel Challenge 等指导与评估资料，非强制法定标准）、11 条核心基准声明，涵盖基准评估与运营建议。

🐍 NumPy 升级与迁移影响

涵盖 NumPy 1.26.4 与 2.0.0 的 5 大核心迁移主题、废弃别名清理与 C-API 变更，提供双版本双向对比；公网站点展示预置影响结构，本地环境支持 AST 静态代码检查。

⚖️ 事实边界与诚实承诺 (Factual Limitations & Honesty Contract)

坚持恪守工程实事求是原则，如实陈述当前实现边界，拒绝任何虚假宣传

公开免登录使用：公开演示站点及本导览手册无需任何登录操作，所有用户均可直接体验 3 大实验场的完整图谱、脑图、资产检索与离线预设问答。

离线预设与在线筛选区分：系统默认使用纯前端确定性规则进行离线预设问答，不依赖外部模型。可选的在线声明选择需登录 ChatGPT 账号，经 Sites Worker + D1 控制全站每日 100 次全局共享额度（北京时间午夜重置），且仅在已收录证据内受控筛选，已有 1 次线上成功调用回执；这与自由生成、流式对话及尚未接通的 MOI 原生搜索截然不同。

未接通服务明确声明：MOI 原生文档知识库自动检索接口与 Memoria 云端记忆同步服务当前尚未接通，请勿将本地探索误认为已直连上述平台服务。用户在浏览器中记录的笔记和复核标记仅保存在客户端 LocalStorage，绝不可称作 Memoria 服务端真实历史记录。

代码分析与公网静态边界：/api/impact 依赖本地 Python 服务运行 AST 静态语法解析，不执行任何用户提交的代码；公网演示站点不包含 Python 运行时，仅提供静态预置的影响样例数据，避免将本地后端接口误认为公网在线能力。

资料性质与无障碍边界说明：酒店资料（ENERGY STAR 清单与 WaterSense H2Otel）定位为行业指导文献而非强制法定标准；天文资料集无软件版本概念；页面提供基础无障碍属性与键盘支持，但未宣称通过完全 WAI-ARIA 认证或全设备屏幕阅读器兼容。

恪守真实边界：系统采用受控结构化请求与确定性规则匹配，专注于已核查证据的事实关联；不宣称任何未证实的比赛提交状态、奖项、企业客户规模、商业节省金额或夸大基准指标。
